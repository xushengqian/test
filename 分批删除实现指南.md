# 分批删除实现指南

## 为什么需要分批删除？

当需要删除大量数据时，一次性删除会导致：
- **长时间持有锁**：阻塞其他操作
- **死锁风险**：多个事务竞争同一资源
- **事务日志过大**：影响数据库性能
- **超时风险**：操作可能超时失败

分批删除可以：
- ✅ 缩短每次锁持有时间
- ✅ 降低死锁概率
- ✅ 避免事务日志过大
- ✅ 可以显示删除进度

## 实现方式

### 方式1：使用 LIMIT 分批删除（推荐）

#### MySQL/MariaDB 实现

```sql
-- 存储过程方式
DELIMITER $$
CREATE PROCEDURE delete_in_batches(
    IN p_index_id BIGINT,
    IN p_index_params VARCHAR(255),
    IN p_batch_size INT
)
BEGIN
    DECLARE v_deleted_count INT DEFAULT 1;
    DECLARE v_total_deleted INT DEFAULT 0;
    
    WHILE v_deleted_count > 0 DO
        DELETE FROM ks_index_user_performance_details
        WHERE index_id = p_index_id 
          AND index_params = p_index_params
        LIMIT p_batch_size;
        
        SET v_deleted_count = ROW_COUNT();
        SET v_total_deleted = v_total_deleted + v_deleted_count;
        
        -- 短暂延迟，释放锁
        SELECT SLEEP(0.05);
    END WHILE;
    
    SELECT v_total_deleted AS total_deleted;
END$$
DELIMITER ;

-- 调用示例
CALL delete_in_batches(123, 'param_value', 1000);
```

#### Java + Spring 实现

```java
package com.example.service;

import org.springframework.jdbc.core.JdbcTemplate;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Propagation;
import org.springframework.transaction.annotation.Transactional;

@Service
public class BatchDeleteService {
    
    private final JdbcTemplate jdbcTemplate;
    private static final int DEFAULT_BATCH_SIZE = 1000;
    
    public BatchDeleteService(JdbcTemplate jdbcTemplate) {
        this.jdbcTemplate = jdbcTemplate;
    }
    
    /**
     * 分批删除 - 使用 LIMIT
     * @param indexId 索引ID
     * @param indexParams 索引参数
     * @param batchSize 每批删除的数量
     * @return 总共删除的记录数
     */
    public int deleteInBatches(Long indexId, String indexParams, int batchSize) {
        int totalDeleted = 0;
        int deletedCount;
        
        do {
            // 每次删除一批
            deletedCount = jdbcTemplate.update(
                "DELETE FROM ks_index_user_performance_details " +
                "WHERE index_id = ? AND index_params = ? " +
                "LIMIT ?",
                indexId, indexParams, batchSize
            );
            
            totalDeleted += deletedCount;
            
            // 每批删除后短暂延迟，释放锁
            if (deletedCount > 0) {
                try {
                    Thread.sleep(50); // 50毫秒延迟
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                    break;
                }
            }
        } while (deletedCount > 0);
        
        return totalDeleted;
    }
    
    /**
     * 分批删除 - 使用独立事务（推荐）
     * 每批使用独立事务，避免长时间持有锁
     */
    public int deleteInBatchesWithNewTransaction(Long indexId, String indexParams, int batchSize) {
        int totalDeleted = 0;
        int deletedCount;
        
        do {
            deletedCount = deleteOneBatch(indexId, indexParams, batchSize);
            totalDeleted += deletedCount;
        } while (deletedCount > 0);
        
        return totalDeleted;
    }
    
    @Transactional(propagation = Propagation.REQUIRES_NEW)
    private int deleteOneBatch(Long indexId, String indexParams, int batchSize) {
        return jdbcTemplate.update(
            "DELETE FROM ks_index_user_performance_details " +
            "WHERE index_id = ? AND index_params = ? " +
            "LIMIT ?",
            indexId, indexParams, batchSize
        );
    }
    
    /**
     * 分批删除 - 带进度回调
     */
    public int deleteInBatchesWithProgress(
            Long indexId, 
            String indexParams, 
            int batchSize,
            ProgressCallback callback) {
        
        int totalDeleted = 0;
        int deletedCount;
        int batchNumber = 0;
        
        do {
            batchNumber++;
            deletedCount = jdbcTemplate.update(
                "DELETE FROM ks_index_user_performance_details " +
                "WHERE index_id = ? AND index_params = ? " +
                "LIMIT ?",
                indexId, indexParams, batchSize
            );
            
            totalDeleted += deletedCount;
            
            // 回调进度
            if (callback != null) {
                callback.onProgress(batchNumber, deletedCount, totalDeleted);
            }
            
            if (deletedCount > 0) {
                try {
                    Thread.sleep(50);
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                    break;
                }
            }
        } while (deletedCount > 0);
        
        return totalDeleted;
    }
    
    @FunctionalInterface
    public interface ProgressCallback {
        void onProgress(int batchNumber, int deletedInBatch, int totalDeleted);
    }
}
```

#### Python 实现

```python
import time
import mysql.connector
from mysql.connector import Error

def delete_in_batches(connection, index_id, index_params, batch_size=1000):
    """
    分批删除数据
    
    Args:
        connection: 数据库连接
        index_id: 索引ID
        index_params: 索引参数
        batch_size: 每批删除的数量
    
    Returns:
        总共删除的记录数
    """
    cursor = connection.cursor()
    total_deleted = 0
    
    try:
        while True:
            # 执行删除
            cursor.execute(
                """
                DELETE FROM ks_index_user_performance_details 
                WHERE index_id = %s AND index_params = %s 
                LIMIT %s
                """,
                (index_id, index_params, batch_size)
            )
            
            deleted_count = cursor.rowcount
            total_deleted += deleted_count
            
            # 提交当前批次
            connection.commit()
            
            print(f"批次删除完成: 本次删除 {deleted_count} 条，累计删除 {total_deleted} 条")
            
            # 如果没有删除任何记录，退出循环
            if deleted_count == 0:
                break
            
            # 短暂延迟，释放锁
            time.sleep(0.05)
            
    except Error as e:
        print(f"删除过程中发生错误: {e}")
        connection.rollback()
        raise
    finally:
        cursor.close()
    
    return total_deleted


# 使用示例
if __name__ == "__main__":

        )

    except Error as e:
        print(f"数据库连接错误: {e}")
    finally:
        if conn.is_connected():
            conn.close()
```

### 方式2：先查询ID再分批删除

适用于需要记录删除的数据或需要更精确控制的情况。

#### Java 实现

```java
public int deleteByIdsInBatches(Long indexId, String indexParams, int batchSize) {
    // 第一步：查询所有要删除的ID（使用索引，速度快）
    List<Long> ids = jdbcTemplate.queryForList(
        "SELECT id FROM ks_index_user_performance_details " +
        "WHERE index_id = ? AND index_params = ?",
        Long.class, indexId, indexParams
    );
    
    if (ids.isEmpty()) {
        return 0;
    }
    
    int totalDeleted = 0;
    
    // 第二步：分批删除ID
    for (int i = 0; i < ids.size(); i += batchSize) {
        int end = Math.min(i + batchSize, ids.size());
        List<Long> batchIds = ids.subList(i, end);
        
        // 构建 IN 子句
        String placeholders = batchIds.stream()
            .map(id -> "?")
            .collect(Collectors.joining(","));
        
        int deleted = jdbcTemplate.update(
            "DELETE FROM ks_index_user_performance_details " +
            "WHERE id IN (" + placeholders + ")",
            batchIds.toArray()
        );
        
        totalDeleted += deleted;
        
        // 短暂延迟
        try {
            Thread.sleep(50);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            break;
        }
    }
    
    return totalDeleted;
}
```

### 方式3：使用游标分批删除（适用于超大数据量）

```java
public int deleteUsingCursor(Long indexId, String indexParams, int batchSize) {
    int totalDeleted = 0;
    
    // 使用流式查询，避免一次性加载所有ID到内存
    jdbcTemplate.query(
        "SELECT id FROM ks_index_user_performance_details " +
        "WHERE index_id = ? AND index_params = ?",
        new Object[]{indexId, indexParams},
        rs -> {
            List<Long> batchIds = new ArrayList<>();
            
            while (rs.next()) {
                batchIds.add(rs.getLong("id"));
                
                // 达到批次大小时，执行删除
                if (batchIds.size() >= batchSize) {
                    deleteBatch(batchIds);
                    totalDeleted += batchIds.size();
                    batchIds.clear();
                    
                    try {
                        Thread.sleep(50);
                    } catch (InterruptedException e) {
                        Thread.currentThread().interrupt();
                        return;
                    }
                }
            }
            
            // 删除剩余的数据
            if (!batchIds.isEmpty()) {
                deleteBatch(batchIds);
                totalDeleted += batchIds.size();
            }
        }
    );
    
    return totalDeleted;
}

private void deleteBatch(List<Long> ids) {
    String placeholders = ids.stream()
        .map(id -> "?")
        .collect(Collectors.joining(","));
    
    jdbcTemplate.update(
        "DELETE FROM ks_index_user_performance_details " +
        "WHERE id IN (" + placeholders + ")",
        ids.toArray()
    );
}
```

## 批次大小选择建议

| 数据量 | 推荐批次大小 | 说明 |
|--------|-------------|------|
| < 1万 | 1000-5000 | 可以一次性删除 |
| 1万 - 10万 | 500-1000 | 平衡性能和锁持有时间 |
| 10万 - 100万 | 200-500 | 减少锁持有时间 |
| > 100万 | 100-200 | 最小化锁持有时间 |

**注意事项**：
- 批次太小：删除效率低，网络往返多
- 批次太大：锁持有时间长，死锁风险高
- 建议从 1000 开始，根据实际情况调整

## 延迟时间选择

- **50-100ms**：适用于一般场景
- **100-200ms**：适用于高并发场景，给其他事务更多机会
- **0ms**：不延迟，适用于低并发或单线程场景

## 完整示例：带错误处理和重试

```java
@Service
public class RobustBatchDeleteService {
    
    private final JdbcTemplate jdbcTemplate;
    private static final int MAX_RETRIES = 3;
    private static final int BATCH_SIZE = 1000;
    
    public RobustBatchDeleteService(JdbcTemplate jdbcTemplate) {
        this.jdbcTemplate = jdbcTemplate;
    }
    
    public int deleteWithRetry(Long indexId, String indexParams) {
        int totalDeleted = 0;
        int deletedCount;
        int consecutiveFailures = 0;
        
        do {
            try {
                deletedCount = deleteOneBatch(indexId, indexParams, BATCH_SIZE);
                totalDeleted += deletedCount;
                consecutiveFailures = 0; // 重置失败计数
                
                if (deletedCount > 0) {
                    Thread.sleep(50);
                }
            } catch (Exception e) {
                consecutiveFailures++;
                log.error("删除批次失败，重试次数: {}/{}", consecutiveFailures, MAX_RETRIES, e);
                
                if (consecutiveFailures >= MAX_RETRIES) {
                    log.error("连续失败 {} 次，停止删除", MAX_RETRIES);
                    throw new RuntimeException("删除操作失败", e);
                }
                
                // 指数退避
                try {
                    Thread.sleep(100 * (long) Math.pow(2, consecutiveFailures));
                } catch (InterruptedException ie) {
                    Thread.currentThread().interrupt();
                    break;
                }
            }
        } while (deletedCount > 0 || consecutiveFailures > 0);
        
        return totalDeleted;
    }
    
    @Transactional(propagation = Propagation.REQUIRES_NEW)
    private int deleteOneBatch(Long indexId, String indexParams, int batchSize) {
        return jdbcTemplate.update(
            "DELETE FROM ks_index_user_performance_details " +
            "WHERE index_id = ? AND index_params = ? " +
            "LIMIT ?",
            indexId, indexParams, batchSize
        );
    }
}
```

## 性能对比

| 方式 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| LIMIT 分批删除 | 简单高效，不需要先查询 | 无法精确控制删除的数据 | **推荐，适用于大多数场景** |
| 先查ID再删除 | 可以记录删除的数据 | 需要两次数据库操作 | 需要记录删除日志的场景 |
| 游标方式 | 内存占用小 | 实现复杂 | 超大数据量（千万级以上） |

## 最佳实践

1. ✅ **使用独立事务**：每批使用 `REQUIRES_NEW` 事务，避免长时间持有锁
2. ✅ **添加延迟**：每批删除后短暂延迟，给其他事务机会
3. ✅ **监控进度**：记录删除进度，便于排查问题
4. ✅ **错误处理**：添加重试机制，处理临时错误
5. ✅ **批次大小**：根据数据量和并发情况调整批次大小
6. ✅ **索引支持**：确保 WHERE 条件有索引支持

## 注意事项

⚠️ **重要提示**：
- 确保 `index_id` 和 `index_params` 有联合索引
- 在低峰期执行大批量删除
- 监控数据库性能，及时调整批次大小
- 考虑使用软删除（UPDATE）代替硬删除（DELETE）
