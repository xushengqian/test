# 线程池线程数设置指南

本项目提供了关于如何正确设置线程池大小的示例代码和最佳实践。

## 📚 线程池大小设置原则

### 1. CPU密集型任务
**公式：线程数 = CPU核心数 + 1**

- **适用场景**：计算、加密、压缩、图像处理等CPU占用高的任务
- **原因**：CPU密集型任务会充分利用CPU，过多的线程会导致上下文切换开销
- **示例**：矩阵运算、数据加密、视频编码

### 2. IO密集型任务
**公式：线程数 = CPU核心数 × (1 + IO等待时间/CPU计算时间)**

- **适用场景**：网络请求、文件读写、数据库查询等IO操作
- **常见设置**：CPU核心数 × 2 到 CPU核心数 × 4
- **原因**：IO操作时CPU处于等待状态，可以运行更多线程
- **示例**：HTTP请求、文件下载、数据库查询

### 3. 混合型任务
**公式：需要根据实际情况调整**

- **常见设置**：CPU核心数 × 1.5 到 CPU核心数 × 2
- **方法**：通过监控和测试找到最佳值

## 🎯 最佳实践

### 1. 监控指标
- **队列长度**：如果队列持续增长，可能需要增加线程数
- **活跃线程数**：观察实际使用的线程数
- **CPU使用率**：CPU密集型任务应保持高使用率
- **响应时间**：确保任务响应时间在可接受范围内

### 2. 动态调整
- 根据系统负载动态调整线程池大小
- 设置合理的最大线程数上限
- 使用合适的拒绝策略处理超出容量的任务

### 3. 避免的问题
- ❌ 线程数过多：导致上下文切换开销，降低性能
- ❌ 线程数过少：无法充分利用系统资源
- ❌ 无界队列：可能导致内存溢出（OOM）
- ❌ 不合理的拒绝策略：可能导致任务丢失

## 🔍 计算公式详解

### CPU密集型
```
线程数 = CPU核心数 + 1
```
额外的1个线程用于处理上下文切换的开销。

### IO密集型
```
线程数 = CPU核心数 × (1 + IO等待时间/CPU计算时间)
```
- 如果IO等待时间是CPU计算时间的10倍，则：线程数 = CPU核心数 × 11
- 实际应用中，通常简化为：线程数 = CPU核心数 × 2 到 CPU核心数 × 4

### 实际应用建议
1. **先设置基准值**：根据任务类型使用上述公式
2. **监控和测试**：观察实际运行情况
3. **逐步调整**：根据监控数据微调线程数
4. **设置上限**：避免线程数过多导致系统资源耗尽

## 📝 注意事项

1. **Java中的GIL**：Python有GIL限制，CPU密集型任务考虑使用进程池
2. **系统资源**：考虑内存、文件描述符等系统限制
3. **任务特性**：不同任务可能需要不同的线程池配置
4. **拒绝策略**：选择合适的拒绝策略处理超出容量的任务
