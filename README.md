# Java 数据库并发查询线程优化项目

本项目演示了如何在Java应用中优化数据库并发查询的线程数设置，实现高性能的数据库访问。

## 🎯 项目目标

- 基于系统资源和数据库连接池优化线程池配置
- 实现动态线程数调整机制
- 提供完整的性能监控和指标收集
- 演示实际的并发查询场景和压力测试

## 🏗️ 架构设计

### 核心组件

1. **ThreadPoolConfig** - 线程池配置类
   - 根据CPU核心数优化线程池大小
   - 针对I/O密集型任务（数据库查询）进行调优
   - 提供多种拒绝策略和监控配置

2. **DatabaseConfig** - 数据库连接池配置
   - 使用HikariCP高性能连接池
   - 基于系统资源动态计算最优连接数
   - 优化连接池参数提升并发性能

3. **DynamicThreadPoolManager** - 动态线程池管理器
   - 实时监控系统负载和线程池状态
   - 根据性能指标自动调整线程数
   - 提供智能的扩缩容策略

4. **PerformanceMonitor** - 性能监控服务
   - 收集查询执行时间、CPU使用率等指标
   - 检测慢查询和连接异常
   - 提供详细的性能报告

5. **ConcurrentQueryService** - 并发查询服务
   - 演示各种并发查询场景
   - 提供压力测试功能
   - 展示异步查询的最佳实践

## 🔧 线程数优化策略

### 1. 基础配置原则

```java
// CPU密集型任务
int corePoolSize = Runtime.getRuntime().availableProcessors();

// I/O密集型任务（数据库查询）
int maxPoolSize = cpuCores * 2;

// 考虑数据库连接池限制
maxPoolSize = Math.min(maxPoolSize, dbConnectionPoolSize * 0.8);
```

### 2. 动态调整算法

- **增加线程条件**：
  - 队列使用率 > 80%
  - 线程使用率 > 90% 且 CPU使用率 < 80%
  - 平均查询时间 > 1000ms 且 CPU使用率 < 80%

- **减少线程条件**：
  - 队列使用率 < 10% 且线程使用率 < 30% 且 CPU使用率 < 30%
  - 平均查询时间 < 100ms 且线程使用率 < 20%

### 3. 连接池配置公式

```java
// 对于数据库密集型应用
int maxPoolSize = cpuCores * 2 + effectiveDiskCount;

// 对于混合型应用  
int maxPoolSize = cpuCores * (1 + avgWaitTime/avgProcessTime);
```

## 📈 配置参数说明

### 线程池配置 (application.yml)

```yaml
thread-pool:
  database-query:
    core-pool-size: 8        # 核心线程数 = CPU核心数
    max-pool-size: 16        # 最大线程数 = CPU核心数 * 2
    queue-capacity: 100      # 队列容量 = 最大线程数 * 5-10
    keep-alive-seconds: 60   # 线程空闲时间
    rejection-policy: "CALLER_RUNS"  # 拒绝策略
```

### 数据库连接池配置

```yaml
spring:
  datasource:
    hikari:
      minimum-idle: 5           # 最小空闲连接数
      maximum-pool-size: 20     # 最大连接数
      connection-timeout: 30000 # 连接超时时间
      idle-timeout: 600000      # 空闲超时时间
      max-lifetime: 1800000     # 连接最大生命周期
```

## 🎛️ 最佳实践

### 1. 线程数设置建议

| 应用类型 | 核心线程数 | 最大线程数 | 队列容量 |
|---------|-----------|-----------|----------|
| CPU密集型 | CPU核心数 | CPU核心数+1 | 较小 |
| I/O密集型 | CPU核心数 | CPU核心数*2 | 较大 |
| 混合型 | CPU核心数 | CPU核心数*1.5 | 中等 |

### 2. 监控关键指标

- **线程池使用率** < 80%
- **队列使用率** < 70%
- **平均查询时间** < 500ms
- **CPU使用率** < 80%
- **连接池使用率** < 80%

### 3. 调优建议

1. **初始配置**：从保守配置开始，逐步调优
2. **压力测试**：在生产环境相似的负载下测试
3. **监控告警**：设置关键指标的告警阈值
4. **定期评估**：根据业务增长调整配置

## 🔍 故障排查

### 常见问题

1. **连接池耗尽**
   - 检查连接泄漏
   - 增加连接池大小
   - 优化查询执行时间

2. **线程池队列满**
   - 增加队列容量
   - 增加最大线程数
   - 优化任务执行效率

3. **CPU使用率过高**
   - 减少线程数
   - 优化查询逻辑
   - 检查是否有死循环

4. **响应时间过长**
   - 检查慢查询
   - 优化数据库索引
   - 增加缓存机制
