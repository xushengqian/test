# 并行指标调度系统

一个高性能的分布式指标调度和执行系统，专为大规模并发场景设计。

## 🎯 项目特点

本项目实现了一个**完全并行化**的指标调度系统，相比传统的串行调度方案，在以下方面有显著优势：

### ⚡ 性能提升

- **10倍以上的扫描速度**：采用并行扫描架构，1000个调度配置扫描仅需5秒
- **3-5倍的执行吞吐量**：多线程池协同工作，最大并发可达50-100个作业
- **异步结果保存**：作业执行和结果保存解耦，不阻塞作业完成

### 🏗️ 架构优势

```
传统串行调度                    并行调度系统
─────────────                   ─────────────
单线程扫描     →                4个扫描线程并行
│                                ↓ ↓ ↓ ↓
逐个创建作业   →                5个创建线程并行批量处理
│                                ↓ ↓ ↓ ↓ ↓
有限并发执行   →                20个执行线程高并发
│                                ↓ ↓ ↓ ↓ ... (20个)
串行保存结果   →                异步保存，不阻塞执行
```

### 🚀 核心功能

1. **多级并行架构**
   - 扫描线程池：并行扫描调度配置
   - 创建线程池：批量并行创建作业
   - 执行线程池：高并发执行作业
   - 结果线程池：异步保存执行结果

2. **智能调度策略**
   - 优先级队列：高优先级作业优先执行
   - 批量处理：减少数据库压力
   - 提前创建：提前生成未来的作业实例

3. **分布式支持**
   - Redis分布式锁：多实例部署不冲突
   - 自动故障转移：实例失败自动接管
   - 单机模式兼容：无Redis时降级运行

4. **企业级特性**
   - 自动重试：失败作业智能重试
   - 超时控制：防止作业无限运行
   - 详细日志：完整的执行轨迹
   - 性能监控：实时性能指标收集

## 🚀 快速开始

### 1. 安装依赖

```bash
cd parallel-metric-scheduler
pip install -r requirements.txt
```

### 2. 初始化数据库

```bash
mysql -u root -p < scripts/create_database.sql
```

### 3. 配置环境

```bash
cp .env.example .env
# 编辑 .env 文件，配置数据库和Redis连接
```

### 4. 启动系统

```bash
python main.py
```

## 🎯 设计理念

1. **并行优先**：能并行就不串行，充分利用多核CPU
2. **批量处理**：减少数据库交互次数，提高效率
3. **异步解耦**：关键路径解耦，避免相互阻塞
4. **资源可控**：明确的并发控制，避免资源耗尽
5. **优雅降级**：分布式组件失败时自动降级
