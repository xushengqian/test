## 性能优化建议

### 1. 根据机器配置调整并发参数

#### 4核8G服务器
```bash
MAX_CONCURRENT_JOBS=30
EXECUTOR_WORKERS=15
JOB_SCAN_WORKERS=3
BATCH_CREATE_WORKERS=3
```

#### 8核16G服务器（推荐）
```bash
MAX_CONCURRENT_JOBS=50
EXECUTOR_WORKERS=20
JOB_SCAN_WORKERS=4
BATCH_CREATE_WORKERS=5
```

#### 16核32G服务器
```bash
MAX_CONCURRENT_JOBS=100
EXECUTOR_WORKERS=40
JOB_SCAN_WORKERS=6
BATCH_CREATE_WORKERS=8
```

### 2. 数据库优化

- **连接池大小**：至少设置为 EXECUTOR_WORKERS 的 1.5倍
- **索引优化**：确保所有查询字段都有索引
- **定期清理**：保留最近30天的数据即可

### 3. Redis优化

- 使用专用Redis实例
- 配置足够的最大内存（建议2GB+）
- 启用持久化（AOF）

### 4. 应用层优化

- **批处理大小**：根据调度配置数量调整
  - <100个：BATCH_SIZE=50
  - 100-1000个：BATCH_SIZE=100
  - >1000个：BATCH_SIZE=200

- **扫描间隔**：根据调度频率调整
  - 高频调度（<5分钟）：JOB_SCAN_INTERVAL=30
  - 中频调度（5-30分钟）：JOB_SCAN_INTERVAL=60
  - 低频调度（>30分钟）：JOB_SCAN_INTERVAL=300

## 监控指标

### 关键性能指标（KPI）

1. **吞吐量**：每分钟完成的作业数
   - 目标：>500个/分钟（8核16G）
   
2. **延迟**：作业从PENDING到开始执行的时间
   - 目标：<30秒
   
3. **成功率**：成功执行的作业占比
   - 目标：>99.5%
   
4. **资源使用率**
   - CPU：60-80%（高效利用，但留有余量）
   - 内存：<4GB（防止OOM）
   
5. **数据库连接数**
   - 目标：<100（防止连接耗尽）

### 监控查询

```sql
-- 实时吞吐量（每分钟）
SELECT 
    COUNT(*) as throughput,
    DATE_FORMAT(actual_end_time, '%Y-%m-%d %H:%i') as minute
FROM job_instances
WHERE status = 'SUCCESS'
AND actual_end_time >= DATE_SUB(NOW(), INTERVAL 10 MINUTE)
GROUP BY minute
ORDER BY minute DESC;

-- 平均延迟
SELECT 
    AVG(TIMESTAMPDIFF(SECOND, scheduled_time, actual_start_time)) as avg_delay_seconds
FROM job_instances
WHERE actual_start_time >= DATE_SUB(NOW(), INTERVAL 1 HOUR);

-- 成功率
SELECT 
    status,
    COUNT(*) as count,
    ROUND(COUNT(*) * 100.0 / SUM(COUNT(*)) OVER(), 2) as percentage
FROM job_instances
WHERE created_at >= CURDATE()
GROUP BY status;
```
