# AI 核心概念：Agent 与 Token

本文档解释了人工智能领域（特别是大型语言模型 LLM）中两个至关重要的概念：**Token（令牌）** 和 **Agent（智能体）**。

## 1. Token (令牌)

### 什么是 Token？
Token 是 AI 模型处理文本的**基本单位**。模型并不直接“阅读”单词或句子，而是先将文本切分成一个个 Token，然后将其转化为数字向量进行计算。

### Token 的构成
Token 的划分方式取决于所使用的**分词器 (Tokenizer)**。
- **英文**：一个 Token 通常是一个单词的一部分，或者一个短单词。平均来说，1000 个 Token 大约等于 750 个英文单词。
  - 例如："smart" -> 1 token
  - "learning" -> 可能被切分为 "learn" + "ing" (2 tokens)
- **中文**：一个 Token 通常对应一个汉字或词组。
  - 例如：“人工智能” -> 可能被切分为 “人工” + “智能” (2 tokens) 或 “人” + “工” + “智” + “能” (4 tokens)，具体取决于模型。

### 为什么 Token 很重要？
1. **计费单位**：大多数商业 API（如 OpenAI, Anthropic）是按 Token 数量收费的（输入 + 输出）。
2. **上下文窗口 (Context Window)**：模型一次能“记住”的信息量是有限的，这个限制通常以 Token 数来衡量（例如 8k, 32k, 128k）。超过这个限制，模型就会“遗忘”之前的信息。
3. **计算复杂度**：生成的 Token 越多，推理所需的时间和算力就越多。

## 2. Agent (智能体)

### 什么是 Agent？
Agent 是一个能够**感知**环境、进行**推理**、并采取**行动**以实现特定目标的系统。在 LLM 时代，Agent 通常指以 LLM 为核心“大脑”，具备自主规划和工具使用能力的系统。

### Agent 的核心组件
一个典型的 LLM Agent 包含以下部分：

1. **大脑 (LLM)**：负责处理信息、逻辑推理、决策规划。它接收 Token 输入，输出行动指令。
2. **感知 (Perception)**：Agent 获取信息的方式，通过 Prompt 将环境状态转化为 Token。
3. **规划 (Planning)**：
   - **子目标分解**：将大任务拆解为小步骤（Chain of Thought）。
   - **反思与修正**：检查自己的行动结果并进行调整。
4. **记忆 (Memory)**：
   - **短期记忆**：当前的上下文窗口。
   - **长期记忆**：通过向量数据库 (Vector DB) 存储和检索的历史信息。
5. **工具使用 (Tool Use)**：Agent 可以调用的外部能力，如：
   - 搜索网络
   - 执行代码
   - 读取文件
   - 调用 API

### Agent 工作流程示例
用户指令：“帮我分析今天的股票市场并写一份报告。”

1. **思考**：Agent 接收指令，规划需要先获取股票数据，再分析趋势，最后写入文件。
2. **行动**：调用 `search_tool` 查询“今日股市行情”。
3. **观察**：获取搜索结果（转化为 Token）。
4. **思考**：分析搜索结果，决定撰写内容。
5. **行动**：调用 `write_file_tool` 生成报告。

---

## 3. 两者的关系

- **LLM (Token Processor) 是 Agent 的引擎**：Agent 的所有思考、规划和决策过程，本质上都是 LLM 处理 Token 序列并预测下一个 Token 的过程。
- **Token 是 Agent 的燃料和带宽**：
  - Agent 能看到的上下文（历史记忆、工具返回结果）受限于 Token 的上下文窗口。
  - Agent 的每一个动作（Action）和观察（Observation）都会消耗 Token。

简而言之：**Agent 是架构在 LLM 之上的自主系统，而 Token 是这个系统内部信息流动的基本原子。**
